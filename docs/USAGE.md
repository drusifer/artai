# artai — Usage

artai turns a manifest (a list of art items) into finished images, in four steps:

```
manifest ──generate──▶ masters/ (full-size originals) ──pack──▶ output_dir/ (web-ready)
                                                         └─review──▶ contact_sheet.html
                                                         └─verify──▶ pass / fail
```

Run it from this checkout after `make install`: `.venv/bin/artai <command> <manifest> [options]`
(or `make run ARGS="<command> <manifest> ..."`).

It is also pip-installable (not on PyPI) into any Python ≥ 3.11 virtualenv, which puts `artai`
on that environment's PATH:

```sh
pip install /path/to/artai                     # from a checkout
pip install git+<repo-url>@<tag-or-commit>      # once the repo is pushed
```

From another project you can also call this checkout by path, e.g. `../artai/.venv/bin/artai`.

Exit codes: **0** success · **1** error (including a mistyped command or option), refused, or some items failed · **2** provider quota
exhausted (re-run later; finished images are skipped) · **130** interrupted with Ctrl-C.

## A complete example

`clans.yaml`:

```yaml
artwork_set:
  name: twelve_clans
  description: The Twelve Clans collectible stickers
  output_dir: game_server/static/stickers   # packed images
  work_dir: build/art/clans                  # masters, logs, claims (default build/artai/<name>)
  theme: Original fantasy clans
  style: bold ink outline, rich painted colours, warm ivory background, no text
  fit: autocrop            # trim background, centre on an exact canvas
  resolution: [512, 512]
  pad: 10
  format: webp
  quality: 92
data_file: cards.json      # JSON list of records, relative to this file
item_template:
  prompt_template: "{clan_look} Depict {name}: evolution level {level} of 3. {style}"
```

```sh
artai prompts clans.yaml                    # check every prompt before spending quota
artai generate clans.yaml --backend codex --parallel 4
artai pack clans.yaml
artai review clans.yaml                     # open the printed contact_sheet.html
artai verify clans.yaml                     # exit 0 only when every image is real, present and correct
artai regenerate clans.yaml --ids dawn-oath-2 --backend codex   # redo a rejected image
artai pack clans.yaml
```

## Commands

| Command | What it does |
|---|---|
| `status <m>` | Prints `set`, `items`, `masters` (real art), `placeholders` (mock art), `packed`, `missing` with up to 8 missing ids, and the quota marker time if the last run hit the quota. Writes nothing. |
| `prompts <m> [--json]` | One `<id><TAB><prompt>` line per item (which is itself a valid TSV manifest). `--json` prints `[{id, filename, prompt, metadata}]`. An unknown `{placeholder}` is warned about on stderr and left in the prompt. |
| `generate <m> --backend B` | Paints every item without a valid master. Resumable: re-running skips finished items. See options below. |
| `pack <m> [--format F] [--quality Q] [--size PX]` | Converts every master into `output_dir/<id>.<format>` (or the item's `output_filename`). Masters that do not open are listed and skipped (exit 1); the previous packed file is kept. |
| `review <m>` | Writes `review_dir/contact_sheet.html`: every item with its image (or "Missing"/"Placeholder"), metadata, prompt, and a filter box. Opens from disk. |
| `verify <m> [--ids ...] [--allow-mock]` | Fails (exit 1) for any item with no packed image, an image that does not open, the wrong size, placeholder (mock) art, or two items with byte-identical images. With `--ids` it says the result covers a sample only. `--allow-mock` accepts placeholder art (for tests). |
| `regenerate <m> --ids A,B --backend B` | Moves the current master and packed image of each id into `work_dir/rejected/<UTC time>/`, then generates them again. Refuses everything if any id is being generated by a live process. Run `pack` afterwards. |
| `unlock <m> --ids A,B` | Removes claims left by a crashed run. Refuses (changing nothing) if a live process still holds one. Usually unnecessary: `generate` takes over dead claims itself. |

### Options on every command

| Option | Meaning |
|---|---|
| `--work DIR` | Work directory (masters, logs, claims, rejected, review). |
| `--out DIR` | Directory for packed images. |
| `--style TEXT` | Style text appended to every prompt (the only way to style a TSV/JSON list). |
| `--fit autocrop\|contain` | How `pack` frames images (and the size `verify` expects). |

Relative paths given on the command line or in a manifest's `*_dir` fields resolve against the
directory you run artai from. `data_file` and `reference_image` resolve against the manifest's folder.

### `generate` / `regenerate` options

| Option | Default | Meaning |
|---|---|---|
| `--backend` | *(required)* | `codex`, `agy`, `gemini`, `command` or `mock`. There is no default, so a forgotten flag can neither spend quota nor write placeholder art. |
| `--parallel N` | 2 | Items generated at once, 1–8. |
| `--retries N` | 2 | Extra attempts after an ordinary failure (so up to N+1 tries). Quota errors are never retried. |
| `--timeout SEC` | 600 | Longest a single provider call may run; it is then killed and counts as a failure. |
| `--min-size PX` | manifest `min_size` (512) | A master whose shorter edge is smaller is invalid and is regenerated. Byte size is never used. |
| `--ids A,B` | all | Only these ids (an unknown id is refused before anything runs). |
| `--reverse` | off | Work from the end of the list — handy for a second terminal. |

**Several terminals at once** are safe: each item is claimed before work starts, and an item
claimed by another live run is reported as "busy" and skipped.

**Quota:** the first quota/rate-limit error stops scheduling new items, writes
`work_dir/.quota-exhausted`, prints how to resume and exits 2. Re-run the same command after
the provider resets. A run that finishes without hitting the quota removes the marker.

**Placeholder art:** `--backend mock` draws offline placeholder images tagged as such. Any real
backend treats them as missing and replaces them; `status` counts them separately; `verify`
fails on them unless `--allow-mock`.

## Backends

| Backend | Needs | Behaviour |
|---|---|---|
| `codex` | Codex CLI logged in | `codex exec --sandbox workspace-write --skip-git-repo-check "<prompt> Save it to <master path>."`, run inside the masters folder. Never uses approval/sandbox bypass flags. |
| `agy` | Antigravity CLI logged in | `agy -p "<prompt>" --output-format json --print-timeout <N>m --sandbox`. If agy saves into its scratch folder instead of the requested path, the newest `<id>.png`/`<id>_N.png` there is moved into place. |
| `gemini` | `GEMINI_API_KEY` | Calls the Gemini image API directly; checks the reply is a PNG. HTTP 429 or a quota message stops the run. |
| `command` | `artwork_set.command` (or GHOT's `cli_command`) in a YAML manifest | Runs your program with `{prompt}`, `{id}`, `{output}` (= `{output_path}`) and `{resolution}` substituted. **No shell**: each placeholder becomes part of one argument, so pipes, redirects and `&&` do not work — wrap them in a script if needed. Exit 0 + a valid image at `{output}` = success. |
| `mock` | nothing | Deterministic offline placeholder art (see above). |

codex and agy prompts start with "Generate a PNG image using your image generation tool —
actual painted raster artwork. Do not write code to draw it." (a coding agent asked plainly for
an image has been seen to write a drawing script instead).

**Reference images:** an item's `reference_image` (path, relative to the manifest) is sent to
`gemini` with the request, and named in the prompt for `codex`/`agy` as a likeness reference.
A missing reference file fails that item with its path.

### Environment variables

| Variable | Used by | Meaning |
|---|---|---|
| `GEMINI_API_KEY` | gemini | Required. Sent only in a request header; never printed or logged. |
| `ARTAI_GEMINI_MODEL` | gemini | Model name (default `gemini-nano-banana-2.1`). |
| `ARTAI_GEMINI_ENDPOINT` | gemini | API URL override (tests, proxies). |
| `ARTAI_CODEX_CLI` | codex | Path of the codex program (default `codex`). |
| `ARTAI_AGY_CLI` | agy | Path of the agy program (default `agy`). |
| `ARTAI_AGY_MODEL` | agy | Pin a model from `agy models` (default: account default). |
| `ARTAI_AGY_SCRATCH` | agy | agy's scratch folder (default `~/.gemini/antigravity-cli/scratch`). |
| `ARTAI_AGY_YOLO` | agy | `1` passes `--dangerously-skip-permissions`; allowed only when exactly one id is selected. |

## Manifests

### YAML set (full form)

`artwork_set` fields — all optional:

| Field | Default | Meaning |
|---|---|---|
| `name` | file name | Set name; also names default folders. |
| `description` | — | Shown on the contact sheet. |
| `work_dir` | `build/artai/<name>` | Masters, logs, claims, rejected, review. |
| `output_dir` | `<work_dir>/out` | Packed images. |
| `review_dir` | `<work_dir>/review` | Where `contact_sheet.html` goes. |
| `theme`, `style` | — | Available as `{theme}`/`{style}`; appended to bare prompts. |
| `default_template` | `{prompt}` | Template for items without their own. |
| `fit` | `autocrop` | `autocrop` or `contain`. Older `autocrop: false` means `contain`. |
| `resolution` | `[512, 512]` | Exact canvas for `autocrop` (`[w, h]` or `"512x512"`). |
| `size` | 512 | Longest edge for `contain`. |
| `pad` | 10 | Margin (px) inside the autocrop canvas. |
| `format` | `webp` | `webp`, `png` or `jpeg`. |
| `quality` | 92 | 1–100. |
| `min_size` | 512 | Smallest acceptable master edge; `generate --min-size` overrides. |
| `command` / `cli_command` | — | Template for the `command` backend. |

Items come from either `items:` or `data_file:`.

```yaml
items:
  - id: fox-1                      # letters, digits, . - _ only; becomes the file name
    prompt: A red fox in snow      # used as-is (+ theme/style appended)
  - id: owl-1
    prompt_template: "{name} on a branch. {style}"
    metadata: {name: Owl}          # every key is a {placeholder}
    output_filename: owl.webp      # optional packed file name
    reference_image: refs/owl.jpg  # optional likeness reference
```

```yaml
data_file: cards.json              # [{id, name, ...}, ...] or {"items": [...]} / {"cards": [...]}
item_template:
  prompt_template: "{name}, {era}. {style}"   # a record's own prompt_template wins
```

Placeholders available in a template: every field of the item's record/metadata, plus `{id}`,
`{prompt}`, `{theme}`, `{style}`, `{set_name}`.

### TSV and JSON lists (recard style)

```
# jobs.tsv — <id><TAB><prompt>; blank lines and # comments ignored; later tabs stay in the prompt
rtg-b-001	A gaunt figure wading knee-deep in black swamp water
```

```json
[{"id": "rtg-b-001", "prompt": "A gaunt figure wading knee-deep in black swamp water"}]
```

Lists use: name = file name, `work_dir` = `build/artai/<name>`, `output_dir` = `<work_dir>/out`,
`fit: contain`, `size: 512`, `quality: 88`, `format: webp`. Style comes from `--style`.

### What is rejected

A duplicate id, an unsafe id (anything but letters, digits, `.`, `-`, `_`), a missing
`data_file`, a TSV line without a tab, a JSON entry without `id`/`prompt`, or invalid YAML/JSON:
artai prints `artai: <file>: <problem>` and exits 1 before writing anything.
